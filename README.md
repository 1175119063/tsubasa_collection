# 翼·时光记

翼·时光记是一套在 Windows 本机运行的个人鸟类观察资料库，包含观察记录、个人图鉴、地点档案和观鸟行程。数据库、照片、缩略图和录音均保存在项目所在磁盘中。

当前有效产品规则见 [DESIGN.md](DESIGN.md)，历史开发过程见 [DEVLOG.md](DEVLOG.md)。

界面精修与多主题外观的后续待办见 [DESIGN.md 第 13.1 节](DESIGN.md#131-界面精修与主题外观待办)：先优化桌面界面，再规划森林、城市、海洋及湿地河流主题。

## 启动

在项目根目录运行：

```powershell
.\start-demo.ps1
```

看到服务启动信息后访问：

```text
http://127.0.0.1:8000
```

同一时间只需启动一个服务进程。如果出现 `Errno 10048`，说明 8000 端口已有一份程序正在运行；关闭旧终端中的服务后再启动即可。

开发启动脚本 `start-demo.ps1` 会监听后端代码变更并自动重载；若已有服务是用旧命令启动的，需要先重启一次。直接使用下方命令启动时，修改 Python 后端后需手动重启，刷新浏览器只会更新前端。

也可以直接调用项目环境：

```powershell
& '.\.conda\envs\tsubasa\python.exe' -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

## 当前界面

Vue 3 前端已经成为唯一正式界面，七个入口分别是探索营地、鸟类调查册、田野记录、区域档案、探索地图、远征日志和收集计划。所有页面直接使用同一套本地数据库，并提供完整的数据录入与管理入口：

- 田野记录：新增、修改、预览和永久删除观察；
- 鸟类调查册：修改简介、分类、生态画像、自定义档案，管理封面、观察凭证和独立 MP3 录音；也可从标题右侧进入由个人观察自动生长的“鸟纲→目→科→属→种”聚焦式分类树；
- 区域档案：新增、修改、上传封面、关联观察和删除区域；
- 远征日志：新增、修改、关联或解除观察、选择封面和删除远征；
- 收集计划：按统一的预设或自定义子项组织已观察物种，主动选择照片凭证、裁切头像并就地预览对应田野记录。
- 探索营地：首页背景可搜索并指定任意一笔已有观察记录，也可恢复为自动使用最新记录；页面下方提供“API 管理”。

旧版和 V2 的 HTML/JavaScript 页面已经移除。旧 `/legacy/*`、`/preview/*` 和 `/vue/*` 书签会以 308 跳转到对应正式页面。

一笔观察代表一次相遇，可以保存同一个体或同一现场连续拍摄的多张 JPEG/JPG；每张不超过 10 MB，并分别保留拍摄时间和所关联的物种。一笔观察最多记录 10 个物种，可指定一张照片作为封面，并可附加多段 MP3。每个物种可以分别填写个体或群体、性别、生命阶段、亚种和备注。

个人分类树支持纠错：选中目、科、属或物种后点击“修改分类”，可更正名称或所属上级，先预览影响范围再保存；目标分类不存在时可补建。移动属或科会调整整个分支，移动单个物种只调整该物种；物种编号和观察媒体保留，重名节点不会自动合并。分类修改统一从个人分类树进入。

田野记录页统一通过“登记新发现”录入，打开照片队列整理界面，支持选择或拖入一张或多张照片，逐张读取拍摄时间。原单笔录入页面和独立“批量导入照片”按钮已移除，首页入口与 `/observations?new=1` 也进入同一界面。可把当前照片的物种、地点和季节应用到勾选的其他照片，再分别校对个体信息、录音和备注。目标物种与季节初始留空；每张照片独立建立一笔观察，同一笔观察需要其他照片时可在“修改记录”中补充。失败项目保留填写内容，成功项目不会重复提交。同一种新鸟只登记一次，后续照片复用它的物种资料。可暂停保存，并在完成后单独关联远征。填写内容仅保留在本次窗口，关闭前请完成保存；保存结果不明时会暂停并提示核实。

## 飞羽精灵

“飞羽精灵”采用接近常见 AI 聊天软件的多轮对话界面，并保留 RPG 探险助手的视觉和语气。默认通过 Ollama 在本机运行 `qwen3.5:2b-q4_K_M`，应用内模型名为 `feiyu-jingling`。当前能力分为两类：

- **精灵对话**：进行一般知识问答、创意讨论、计划梳理和连续对话；涉及本项目功能时会参考内置页面说明；
- **受约束工具**：从用户粘贴的原文提取分类字段，以及用自然语言查询田野记录。

受约束工具具体包括：

- 在新增物种时，从粘贴的原文中提取目、科、属、种、亚种及中拉名称，预览后再填写表单；
- 在田野记录中，把自然语言转换为参数化只读查询，支持精确日期、日期范围、多个物种、同框记录、目科属种、地点和远征等组合条件；
- 依据项目内置说明介绍当前页面的功能。

模型不会代替用户保存资料。分类抽取只允许抄录原文明确出现的信息；田野查询只能访问两个受限只读视图，并由本地程序校验和执行，不能修改资料库。首次推理需要加载模型，可能比后续请求稍慢。

首页下方的“API 管理”可以将飞羽精灵切换为任意兼容 OpenAI Chat Completions 协议的外部模型，需要填写 HTTPS Base URL（通常以 `/v1` 结尾）、模型名称和 API Key。切换后开放式精灵对话和田野记录查询 skill 使用所选外部模型；分类字段提取和页面功能说明仍使用本地 Ollama。外部聊天直接接受自然语言结果；田野查询要求模型生成严格的结构化查询计划，并只把查询说明、只读视图结构和用户问题发往外部服务，数据库查询仍在本机执行。相关内容会受外部服务商的隐私政策约束。

首次部署或迁移到另一台电脑时，先安装并启动 Ollama，再运行：

```powershell
.\packaging\ollama\setup.ps1
```

新增物种表单还提供“查阅本地资料”。把合法取得的 PDF、TXT 或 Markdown 放入
`data/knowledge/` 后，飞羽精灵会按鸟名检索原文片段，再生成带出处的分类填写建议。
该功能不内置完整鸟类名录、不自动建立全量分类数据库，也不会直接保存建议；资料不足或无法
确定亚种时会保留空值。详细使用和资料元数据格式见
[docs/KNOWLEDGE-LIBRARY.md](docs/KNOWLEDGE-LIBRARY.md)。

模型状态可用 `ollama list` 和 `ollama ps` 检查，详细设置见 [packaging/ollama/README.md](packaging/ollama/README.md)。

## API 管理与地图

首页“API 管理”统一维护高德地图 Web 服务 Key、天地图浏览器端 Key 和飞羽精灵的模型提供方。配置摘要不会回显完整 Key，服务端以跨平台本地 JSON 格式保存到 `data/integrations.dat`，因此不绑定特定操作系统、用户或机器；该文件含有明文密钥，应依赖本机账户与目录权限保护。该文件不进入资料库 ZIP 备份，换电脑后应重新填写或单独安全迁移。

Leaflet 脚本和样式随正式前端在本机提供。配置天地图浏览器端 Key 后，地点选点与探索地图优先使用天地图矢量底图和中文注记，并可手动切换 OpenStreetMap；天地图初始加载失败或超时会自动切换备用底图。未配置天地图时直接使用 OpenStreetMap。地点中文搜索与逆地理编码继续由高德 Web 服务完成，这里需要的是高德“Web 服务”类型 Key，不需要 JavaScript API 的安全密钥。天地图 Key 属于浏览器端密钥，页面请求瓦片时必然会携带它。

天地图 Key 可在[天地图控制台](https://console.tianditu.gov.cn/api/key)申请，应用类型选择浏览器端；保存后可在 API 管理中执行连接测试。

协议、模型路由和安全边界详见 [docs/API-MANAGEMENT.md](docs/API-MANAGEMENT.md)。

## 本地数据与备份

真实数据保存在项目根目录的 `data` 中，包括 SQLite 数据库及所有导入媒体。该目录已被 Git 忽略，不属于源代码。

首页提供完整备份与恢复。备份使用 SQLite 在线快照，并将数据库、照片、缩略图、录音及逐文件 SHA-256 清单打包到程序旁的 `backups` 目录。恢复前自动备份当前状态；所选 ZIP 只有通过路径安全、清单哈希、SQLite 完整性、必要数据表、媒体引用和原始媒体哈希校验后才会替换当前资料。出于密钥安全考虑，`data/integrations.dat` 不进入备份，也不会在恢复时被替换。

田野记录页可以导出 UTF-8 CSV；多物种照片按物种条目分别占一行并共享观察 ID。区域档案提供跨区域探索地图、相邻点位聚合及名称和区域类型筛选。鸟类调查册可以删除不再需要的独立物种录音。

数据库结构使用 Alembic 管理版本，软件启动时会自动升级已有资料库。检测到待迁移数据库时，程序会先在 `backups` 中生成通过完整性检查的灾前数据库快照；升级软件前仍建议手动创建一份包含媒体的完整备份。

## Windows 发行包

公开仓库只构建不含任何个人记录的空白版。目录版解压后应保留整个目录结构，再双击 `翼·时光记.exe`；不要只复制 EXE 文件。安装器采用当前用户范围安装，升级与卸载均保留 `data`、`backups` 和 `updates`。

发行版可以通过 `TSUBASA_UPDATE_MANIFEST_URL` 配置 HTTPS 更新清单。软件只下载版本号更高且 SHA-256 完全匹配的安装包，不会在运行中自覆盖；使用者应先完整备份，关闭软件后再运行安装包。推送 `v*` 标签后，GitHub Actions 会自动构建 Windows 便携包和 macOS Docker 部署包并创建 Release。

打包脚本不会读取项目根目录中的 `data`。数据库、照片、录音、备份、密钥配置与生成的发行包均不进入版本控制。
